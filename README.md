# Таблица без зубрёжки: проект для размещения на своём хостинге

Статический сайт. Сервер только отдаёт файлы. Прогресс хранится в браузере (IndexedDB), аккаунтов, аналитики и форм нет.

## Файлы

| Файл | Что это |
|---|---|
| `index.html` | лендинг (главная страница сайта), картинка `img/hero.png` |
| `trainer.html`, `app.js`, `app.css` | сам тренажёр (кнопка «Попробовать бесплатно» ведёт сюда) |
| `fonts.css`, `fonts/` | локальные шрифты (файлы `.woff2` нужно положить, см. шаг 1) |
| `how.html`, `offer.html`, `privacy.html`, `notice.html` | «Как хранятся данные», оферта, политика конфиденциальности, уведомление (черновики, поля в `[скобках]`) |
| `manifest.json`, `service-worker.js`, `icons/` | установка на устройство и офлайн-режим |
| `_headers` | заголовки безопасности для Netlify и Cloudflare Pages |
| `tools/get-fonts.mjs` | скачивает шрифты в `fonts/` |
| `tools/make-codes.py` | делает коды доступа |
| `src/`, `build.py` | исходники и сборка страниц `how/offer/notice` и предпросмотра |

## Шаг 1. Положить шрифты (один раз, 5 минут)

В среде, где я готовил проект, внешние сайты закрыты, поэтому скачать шрифты я не смог. Сделайте у себя (нужен Node.js 18+):

```
cd tools
npm init -y
npm i @fontsource/rubik @fontsource/nunito @fontsource/caveat
node get-fonts.mjs
```

В папке `fonts/` появятся 10 файлов `.woff2`. Шрифты Rubik, Nunito и Caveat распространяются по лицензии SIL OFL, их можно размещать на своём сайте. Пока файлов нет, сайт работает на системных шрифтах, просто выглядит чуть иначе.

## Шаг 3. Размещение

**GitHub Pages.** Создайте репозиторий, загрузите содержимое папки (без `src/`, `build.py`, `tools/`, если не нужны). Settings → Pages → Deploy from branch → `main`, папка `/ (root)`. Файл `_headers` GitHub Pages игнорирует, заголовки безопасности там не настроить, но тег CSP в страницах уже есть.

**Netlify.** Перетащите папку на app.netlify.com/drop. Заголовки из `_headers` подхватятся сами.

**Cloudflare Pages.** Create project → Direct Upload → загрузите папку. `_headers` тоже подхватится.

Важно: сайт должен открываться по `https://`. Без него service worker и установка не работают.

## Шаг 4. Оплата без форм на сайте

На сайте нет полей для карты, имени, почты и телефона. Кнопка «Купить» это обычная ссылка на страницу агрегатора (ЮKassa, CloudPayments, Robokassa и т.п.).

**Вариант A, простой (реализован).** Вы создаёте набор кодов: `python3 tools/make-codes.py standard 100` и `python3 tools/make-codes.py pro 100`. Хеши вставляете в `CODES_STD` и `CODES_PRO`, сами коды выдаёте покупателям: либо загружаете в агрегатор/на страницу «Спасибо», либо отправляете вручную. Покупатель вводит код, и доступ открывается локально.
Плюсы: сервера и персональных данных нет. Минусы: код можно передать другому человеку, а хеши лежат в `app.js` (подобрать случайный код вида `XXXX-XXXX-XXXX` нереально, но защита от пересылки только организационная). Кроме того, каждый платёж нужно сопровождать выдачей кода: либо вручную, либо настроив страницу успеха агрегатора. Не все тарифы агрегаторов позволяют показать уникальный код, уточните у вашего.

**Вариант B, сложнее.** Вебхук агрегатора на ваш сервер, который выдаёт одноразовый код. Тогда появляется сервер, который хранит `payment_id` и сумму, но не персональные данные. Это даёт защиту от пересылки кодов, но нарушает «ни одного сервера», и его придётся поддерживать.

Рекомендация для вашей модели: вариант A, пока продаж немного.

После выбора агрегатора замените `PAY_URL_STD` и `PAY_URL_PRO` и заполните `[название платёжного сервиса]` в `how.html`, `notice.html`, `offer.html` (или в `build.py`, затем `python3 build.py`).

## Шаг 5. Проверка перед запуском

Внешних запросов — 0. Проверьте сами: откройте сайт, DevTools (F12) → Network → обновите страницу. Все строки должны быть с вашего домена. Фильтр «Third-party» должен быть пустым.

Что загружается: `index.html`, `app.js`, `app.css`, `fonts.css`, `manifest.json`, 9 файлов шрифтов, иконки. Всё с вашего домена. Скриптов сторонних, iframe, пикселей, аналитики нет. Это закреплено и заголовком CSP (`default-src 'self'`): браузер сам заблокирует любой чужой запрос.

Чек-лист:
- [ ] прогресс сохраняется после перезагрузки;
- [ ] «Родителям» → «Экспортировать прогресс» скачивает `progress-ГГГГ-ММ-ДД.json`, «Импортировать прогресс» показывает, что изменится, и просит подтвердить;
- [ ] Chrome → значок установки в адресной строке → приложение ставится;
- [ ] DevTools → Application → Service Workers: статус «activated»; Network → Offline → страница открывается;
- [ ] Network: запросов на чужие домены нет;
- [ ] «6+» виден на главной и в футере;
- [ ] ссылки «Как хранятся данные», «Оферта», «Уведомление» открываются;
- [ ] на бесплатном тарифе блок 3 ведёт на экран тарифов, кнопки идут на `PAY_URL_STD` и `PAY_URL_PRO`, верный код открывает нужный тариф; тестовые коды TEST-STANDARD и TEST-PRO удалены.

Обновляя сайт, меняйте `VERSION` в `service-worker.js`, иначе у пользователей останется старая версия из кэша.

## Продвинутый режим

Переключатель «Продвинутый режим» в шапке. Выключен по умолчанию: базовая версия работает как раньше. Состояние сохраняется в прогрессе.

| Функция | Как работает |
|---|---|
| Повторения по расписанию | Каждый пример в «коробках»: верно с первого раза → следующая пауза 1, 3, 7, 14, 30 дней; ошибка → снова сегодня. Тренажёр берёт до 4 примеров к повтору, до 2 новых, остальное по слабым местам |
| «Что ты помнишь» | Перед каждым блоком один вопрос на угадывание, без оценки и без статистики |
| Чередование и выбор приёма | В тренажёре примеры перемешаны, а перед некоторыми нужно выбрать приём (ноль справа, удвоить, десять минус и т.д.) |
| Задачи с историей | Умножение, деление по группам и деление поровну; в блоках и в тренажёре |
| Объясни вслух | После последнего шага блока: вопрос ребёнку, подсказка родителю, отметка «рассказал». Список вопросов в «Родителям» |
| Игры | Найди пару, найди ошибку, собери прямоугольник, счёт через n |
| Три цели дня | 5 примеров, 1 повтор в тренажёре, 1 игра |
| Итоговая проверка | 30 разных примеров, без подсказок и таймера, цель 90% |

Настройки в `app.js`: `FINAL_N=30` и `FINAL_PASS=90` (число примеров и порог). Если меняете порог, поменяйте его и в оферте (`build.py`, раздел «Гарантия»).

Формат файла прогресса теперь `schemaVersion: 3` (добавлены `sr`, `daily`, `final`, `told`). Файлы версий 1 и 2 импортируются.

## Продвинутый режим, этап 2

Всё ниже включается только переключателем «Продвинутый режим». Базовая версия не изменилась.

- **Трудные примеры**: 6×7, 6×8, 7×8, 7×9, 8×9 с картинкой, приёмом, своей заметкой ребёнка и мини-тренировкой. На главной предлагается пример, в котором ребёнок чаще всего ошибается.

- **Примеры из жизни**: монеты по 10 рублей, колёса, часы.

- **Родителю**: совет дня после занятия, строка «За неделю…» в разделе «Родителям».
- **Печать**: файлы `print.html` и `print.js` (квадрат Пифагора и карточки трудных примеров). Работает только на своём хостинге, в превью-артефакте печати нет.
- Данные: схема прогресса v4 (добавлены `notes` и `stk`). Файлы версий 1–3 по-прежнему импортируются.
- После выкладки обновите `VERSION` в `service-worker.js` (сейчас `v4-2026-10-25`).

**Что настроить перед запуском**

1. `PAY_URL_STD` и `PAY_URL_PRO` в начале `app.js`: ссылки на страницы оплаты платёжного сервиса. Лендинг подхватывает их сам при `python3 build.py`.
2. Коды. Сейчас в `CODES_STD` и `CODES_PRO` лежат **тестовые** коды `TEST-STANDARD`, `TEST-PRO` и `1111` (открывает «Продвинутый»; слабый код, удалите его первым). Перед запуском удалите их и подставьте свои: `python3 tools/make-codes.py standard 100`, затем `python3 tools/make-codes.py pro 100`. Строки из вывода вставьте в `app.js`, сами коды загрузите в платёжный сервис.
3. Пересоберите страницы: `python3 build.py`, поменяйте `VERSION` в `service-worker.js`.
4. Заполните `[поля]` в оферте, политике и на лендинге (контакты).

**Мягкая защита.** Сайт статический, поэтому тариф хранится в браузере. Человек, который умеет пользоваться инструментами разработчика или править файл прогресса, может открыть тариф без оплаты. Это ожидаемо для такой схемы: она защищает от случайного обхода, а не от намеренного. Если нужна настоящая защита, потребуется сервер с проверкой оплаты, и тогда сервис перестанет быть полностью локальным.

**Скриншот на лендинге** (`img/hero.png`) сделан без шрифтов проекта. После того как положите шрифты (шаг 1), откройте `trainer.html`, начните блок «Умножаем на 1 и на 10» и сделайте новый скриншот карточки урока с тем же именем.

Лимит 10 минут считается по активному времени в уроках и тренажёре, на странице «Квадрат» время идёт, но она не блокируется. Лимит закрывает уроки и тренажёр при следующем переходе, а не посреди вопроса.

## Блог и SEO

**Как устроен блог.** Статьи лежат в `blog_data.json`: у каждой есть `slug`, `title`, `h1`, `description`, `keywords`, `author`, `date`, `read` (время чтения) и `body` — список блоков. Блок `"## Заголовок"` даёт H2, `"### Заголовок"` даёт H3, строки с `"- "` складываются в список, остальное абзацы. Ссылки внутри текста: `[текст](blog:slug-другой-статьи)` на статью блога, `[текст](trainer)` на тренажёр, `[текст](https://…)` на внешний сайт.

`python3 build.py` по этим данным создаёт `blog.html` (карточки: заголовок, описание, дата, время чтения), страницы `blog-<slug>.html` (автор, дата, время чтения, CTA в начале и в конце, блок «Читайте также», хлебные крошки), `sitemap.xml`, `robots.txt` и обновляет список страниц в `service-worker.js`. Чтобы добавить статью, допишите объект в `articles` и запустите сборку, а потом поднимите `VERSION` в `service-worker.js`. Объём текста лучше держать в пределах 4000–6000 знаков.

**Обязательно перед выкладкой**

1. Укажите адрес сайта: `SITE_URL=https://ваш-домен.ru python3 build.py`. Сейчас везде стоит `https://example.com`, и от этого зависят canonical, `og:url`, `sitemap.xml`, `robots.txt` и JSON-LD.
2. В начале `build.py` заполните `CONTACT_EMAIL` и `CONTACT_TG`, иначе на странице «Связаться с нами» остаются заглушки. Остальные `[поля]` на страницах «О нас», «Для партнёров» и в юридических текстах заполните вручную в `build.py`.
3. Опубликуйте на хостинге только файлы сайта: `*.html`, `app.js`, `app.css`, `fonts.css`, `landing.js`, `print.js`, `service-worker.js`, `manifest.json`, `sitemap.xml`, `robots.txt`, `_headers`, папки `img/`, `icons/`, `fonts/`. Файлы `build.py`, `blog_data.json`, `reviews.json`, `tools/`, `README.md`, `HANDOFF.md` на хостинг выкладывать не нужно.
4. Зарегистрируйте сайт в Яндекс Вебмастере и Google Search Console, добавьте `sitemap.xml`.

**Разметка Schema.org** (JSON-LD, не выполняется как скрипт, поэтому строгая политика CSP ей не мешает): на главной `SoftwareApplication` (с тремя предложениями цены) и `FAQPage` (вопросы те же, что на странице), на страницах статей `Article`, на `blog.html` `Blog`. Рейтингов и отзывов в разметке нет, и добавлять их без настоящих данных нельзя.

**Что в мета-данных.** Для каждой страницы уникальные `title`, `description`, `keywords`, canonical, Open Graph и Twitter Cards. Картинка для соцсетей: `img/og.png` (1200 × 630). Яндекс и Google теги `keywords` не учитывают, они оставлены по требованию заказчика.

**Статья про методику Ахмадуллина** написана как нейтральный обзор по открытому описанию книги на сайте «Читай-город»: мы не связаны с автором, утверждения о сроках («за три дня») названы словами автора, эффективность не оценивается.
